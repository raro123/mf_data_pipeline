# Mutual Fund Data Pipeline

Python data pipeline for collecting and preparing Indian mutual-fund data from
AMFI, with optional Zerodha instrument data and NIFTY benchmark data.

The repository currently uses a hybrid architecture:

- Cloudflare R2 is the operational store for scheduled NAV, metadata, AUM, and
  benchmark jobs.
- Local CSV and Parquet files under `data/` support historical backfills,
  metadata cleaning, master-data maintenance, and exploratory analysis.
- DuckDB is used for R2 access, joins, validation queries, and Parquet output.
- Pandas is used for API response parsing and local transformations.
- GitHub Actions schedules the production jobs.

## Data Products

| Product | Purpose | Current destination |
| --- | --- | --- |
| Raw historical NAV | AMFI NAV history downloaded in date chunks | `data/raw/nav_historical/` and R2 |
| Raw daily NAV | Missing weekday NAV snapshots from AMFI | R2 `mutual_funds/raw/` |
| Clean daily NAV | NAV joined to scheme metadata, limited to growth plans | R2 `mutual_funds/clean/nav_daily_growth_plan.parquet` |
| Scheme metadata | AMFI scheme attributes and plan classification | Local `data/processed/scheme_metadata/` |
| Scheme master data | All schemes ever observed, including inactive schemes | Local `data/processed/scheme_metadata/` |
| Scheme-wise AUM | Quarterly AMFI average AUM | Local dated Parquet and R2 `mutual_funds/aum/` |
| NIFTY benchmarks | NIFTY index data copied from an upstream R2 Delta table | R2 `mutual_funds/clean/mf_benchmark_nifty.parquet` |

R2 paths are generated by `config.settings.R2` using this pattern:

```text
r2://financial-data-store/mutual_funds/<area>/<file>.parquet
```

## Current Automated Workflows

| Workflow | Schedule | Commands |
| --- | --- | --- |
| Daily NAV processing | Daily at 04:00 UTC / 09:30 IST | `fetch_daily_nav`, then `daily_nav_clean` |
| Scheme metadata extraction | Saturday at 01:00 UTC / 06:30 IST | `extract_scheme_metadata` |
| Benchmark loading | Daily at 18:30 UTC / 00:00 IST next day | `load_benchmark_data` |

Every workflow also supports manual execution from the GitHub Actions tab.

## Setup

Python 3.9 or newer is recommended. The workflows currently use Python 3.9
for NAV and benchmark jobs and Python 3.12 for metadata extraction.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -c "from config.settings import initialize_project; initialize_project()"
```

Create a local `.env` with the R2 credentials required by operational jobs:

```text
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_ACCOUNT_ID=...
```

Optional API, retry, logging, and processing settings are documented in
`config/settings.py`.

## Running The Pipeline

Historical NAV backfill:

```bash
python -m scripts.fetch_historical_nav --start 20060101
python -m scripts.transform_historical_nav
```

Daily R2 NAV update:

```bash
python -m scripts.fetch_daily_nav
python -m scripts.daily_nav_clean
python -m scripts.generate_nav_validation_report
```

`fetch_daily_nav` derives its checkpoint from dated raw objects under
`mutual_funds/raw/nav_daily_*.parquet`; it does not depend on a clean NAV
output. Scheduled gap filling runs through yesterday so it does not request the
current day's NAV before publication. On an empty raw prefix, initialize
explicitly with:

```bash
python -m scripts.fetch_daily_nav --bootstrap-date YYYYMMDD
```

`daily_nav_clean` is temporarily retained in the scheduled workflow for
legacy consumers. The datalake independently builds canonical `mf.nav_daily`
and `mf.nav_daily_open_growth` datasets from raw NAV files.

Local scheme metadata and master-data refresh:

```bash
python -m scripts.clean_scheme_metadata
python -m scripts.build_scheme_masterdata
```

The local cleaner expects timestamped AMFI CSV files in
`data/raw/scheme_metadata/`. The scheduled `extract_scheme_metadata` job writes
raw Parquet directly to R2 instead, so these paths are not yet one continuous
workflow.

Optional jobs:

```bash
python -m scripts.fetch_aum_data
python -m scripts.fetch_aum_data --years 3
python -m scripts.load_benchmark_data
python -m scripts.ingest_zerodha_mf
```

See `PIPELINE_EXECUTION_ORDER.md` for prerequisites and detailed ordering.

## Repository Layout

```text
config/                 Central paths, API settings, validation, and R2 setup
scripts/                Executable ingestion and transformation modules
utils/                  Shared NAV and logging helpers
.github/workflows/      Scheduled GitHub Actions jobs
data/                   Local raw, processed, and report artifacts (gitignored)
flat_files/             Manually maintained reference inputs
notebooks/              Exploratory analysis
```

## Important Current Limitations

- The R2 metadata extractor and the local metadata cleaner use different
  storage handoffs. The scheduled metadata workflow does not currently clean
  metadata or rebuild scheme master data.
- `transform_historical_nav.py` loads all historical CSV files into Pandas
  before writing Parquet. It is not currently a streaming or DuckDB-native
  transformation.
- The large local combined and analytical Parquet files are retained snapshots
  from an older pipeline generation; no current script rebuilds them.
- NAV validation exists as a manual script but is not part of the daily GitHub
  Actions workflow.
- The scheduled daily workflow still rebuilds the legacy R2
  `clean/nav_daily_growth_plan.parquet` output after raw extraction. Raw
  extraction no longer depends on that file, allowing this step to be retired
  after consumer verification.
- Unit coverage currently focuses on daily NAV checkpoint and gap behavior.
  `test_github_actions_setup.py` remains a separate environment and
  connectivity diagnostic rather than a unit test.

## Migration Status
